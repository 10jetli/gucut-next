# บันทึกการใช้ช่องข้ามด่าน — ตารางนี้อยู่ใน git **โดยเจตนา**

🔑 **ทำไมต้องมีไฟล์นี้** (14 ต.ค. 2569 — เกณฑ์สามข้อที่ผมเขียนเอง แล้วส่องตัวเองเจอ)
เกณฑ์: *ช่องยกเว้นต้องตอบได้ว่า **ใครตรวจแทน** · ตอบไม่ได้ ⇒ ต้องจ่ายด้วย **การบังคับอธิบาย***
⇒ ส่องช่องยกเว้นในรีโปนี้แล้วพบว่าสองช่องที่ **ทรงอำนาจที่สุด** จ่ายไม่ครบทั้งสามข้อ:

| ช่อง | ใครตรวจแทน | บังคับอธิบาย | โชว์ทุกรอบ |
|---|---|---|---|
| `SKIP_PREPUSH=1` | ไม่มี | ✗ | ✗ |
| `ALLOW_COMMIT_DURING_PUSH=1` | ไม่มี | ✗ | ✗ |

⇒ ⇒ ใช้แล้ว **ไม่เหลือร่องรอยที่ไหนเลย** ทั้งที่มันข้ามด่านทั้งอัน
🔑 เหตุที่มองข้ามมาทั้งวัน (ฝั่งท่อเจอข้อเดียวกันและตั้งชื่อให้):
   **ของที่เราเป็นคนบอกทางออกเอง เราไม่นับว่าเป็นช่องยกเว้น**
   — ฮุคพิมพ์วิธีข้ามตัวเองทุกครั้งที่มันตีกลับ ⇒ มันดูเหมือน "คำแนะนำ" ไม่ใช่ "ประตู"

## 🚫 เจตนา: ให้การข้ามเป็น **การตัดสินใจที่มีร่องรอย** ไม่ใช่สิ่งที่ทำไม่ได้
ด่านที่ลงโทษพฤติกรรมที่จำเป็น **จะถูกเลี่ยง** แล้วเราเสียทั้งด่านและร่องรอย
⇒ จึง **ไม่บล็อก** · บังคับแค่ `BYPASS_WHY` และจดลงตารางนี้

## 🔴 ขอบเขตที่เลขในตารางนี้ **ตอบไม่ได้** — อ่านก่อนใช้เลข
`git push --no-verify` **ข้ามฮุคตั้งแต่ก่อนโค้ดบรรทัดแรกจะรัน** ⇒ ตัวจดอยู่ในฮุค ⇒ **ไม่ได้รัน**
⇒ ⇒ ไม่มีแถวในตาราง **และไม่มีอะไรฟ้องที่ไหนเลย**
🔑 **เลขนี้นับเฉพาะ "ช่องที่ผ่านฮุคถูกใช้กี่ครั้ง" ไม่ใช่ "ด่านถูกข้ามกี่ครั้ง"**
   ⇒ ⇒ **0 ครั้ง ไม่ได้แปลว่าไม่มีใครข้ามด่าน**
📌 และปิดด้วยฮุคไม่ได้โดยหลักการ — สิ่งที่ถูกข้ามคือ **กลไกที่เรียกโค้ดเรา** ไม่ใช่โค้ดเรา
   (ฝั่งท่อวัดและชี้ข้อนี้ 14 ต.ค. 2569 · กฎ: **ตัวบันทึกที่อยู่ในของที่ถูกข้ามได้
   จะบันทึกไม่ได้ตอนที่สำคัญที่สุด** — รูปเดียวกับ `check-chain-floor` ที่ต้องอยู่นอกสาย)
⚠️ ที่ตรวจแทนได้จริงอยู่ **ฝั่งปลายทาง** (คอมมิตบน origin ที่ไม่มีผล build ตรงกัน)
   **ยังไม่ได้ทำทั้งสองฝั่ง** — เขียนไว้ว่ายังไม่มี ไม่ใช่ว่ามีแผน

## 🔴 และแถวในตารางนี้เคยถูก **เทสของผมเอง** เขียนปน (14 ต.ค. 2569)
เทส `ด่านตอนพิมพ์-commit` ยิงฮุคด้วยช่องยกเว้นเพื่อพิสูจน์ว่าทางออกเดินได้
⇒ `git rev-parse --show-toplevel` ชี้กลับมาที่รีโปจริงแม้เทสรันจากที่ทดลอง ⇒ **ได้แถวปลอม 1 แถว**
⇒ แก้ด้วยช่องฉีดพาธ `BYPASS_LOG` (ท่าเดียวกับ `TEST_FLOOR_FILE`) · ลบแถวปลอมแล้ว
🔑 **ร่องรอยที่ปนของเทส ทำให้ตารางตอบ "ใครข้ามด่านจริง" ไม่ได้อีก** — คลาส: เทสทำลายของที่มันตรวจ

## 🔴 ตารางนี้เคย **อ้างเกิน** ว่าครอบสองช่อง — ของจริงมีทางเงียบอีกสองทาง
ฝั่งท่อพบว่าช่อง `ALLOW_FAST_PUSH` ของเขา **ไม่เคยถูกจดเลย** ทั้งที่คอมมิตเขาเขียนว่าจดแล้ว
⇒ ผมไล่ **ทุกทางออกก่อนกำหนด** ของฮุคผม (`exit 0` ทุกจุด) แล้วเจอสองทางที่ทำให้ด่านเงียบ **โดยไม่มีแถว**:
```
pre-push:68   ไม่พบ node ≥22 ⇒ ข้ามทั้งด่าน      ⇒ เดิมไม่จด ⇒ จดแล้ว (NODE_TOO_OLD)
pre-commit:47 ธงเก่ากว่า 2 ชม. ⇒ ไม่บล็อก        ⇒ เดิมไม่จด ⇒ จดแล้ว (STALE_FLAG)
```
🔑 ⇒ ตารางเดิมครอบ **ช่องที่คนเลือก** แต่ไม่ครอบ **ความเงียบที่สภาพแวดล้อมเปิดให้**
   และคำว่า "ครอบสองช่อง" ที่ผมเขียนใน `7ee34df4` **เกินจริงตั้งแต่วันแรก**
⚠️ คลาสที่ฝั่งท่อตั้งชื่อ: **คำกล่าวอ้างเรื่องความครอบคลุมที่เราเขียนเอง
   ถูกเอาไปใช้เป็นข้อมูลตั้งต้นของการอนุมานในภายหลัง** ⇒ ลิสต์เหตุที่สร้างจาก
   "ช่องที่เราคิดว่าปิดแล้ว" **จะตัดเหตุจริงออกโดยไม่มีใครรู้**

### 🧪 สถานะการพิสูจน์ (เขียนแยก เพราะไม่เท่ากัน)
· `STALE_FLAG` ⇒ **พิสูจน์ด้วยการรันจริง** ✅ ได้แถว `| … | STALE_FLAG | … |` และตารางจริงไม่ถูกแตะ
· `NODE_TOO_OLD` ⇒ **ยืนยันด้วยการอ่านโค้ดเท่านั้น** 🔶 ยังไม่ได้รันจริง
  เหตุ: จำลอง "ไม่มี node ≥22" ต้องตัด node ออกจาก PATH ⇒ ฮุคเดินต่อไปถึงขั้นที่ใช้เครือข่าย/`npm run build`
  ⇒ ค้างทุกครั้งใน 60 วิ (ลองสามท่า: PATH ว่าง · PATH ปลอม · ปิด stdin) ⇒ **ยังไม่สำเร็จ**
  ⇒ ⇒ จึงเขียนว่า **"ยังไม่ได้พิสูจน์"** ไม่ใช่ "พิสูจน์แล้ว" — และนี่คือหนี้ที่ค้างไว้จริง

## 📏 ราคาที่จ่ายแทน "ใครตรวจแทน"
① `BYPASS_WHY` ต้อง ≥20 อักขระ (มีช่องว่างได้) — ไม่ใส่ ⇒ ยังข้ามได้ แต่จดว่า **"ไม่ให้เหตุ"**
② ฮุคพิมพ์ **"ช่องข้ามด่านถูกใช้มาแล้ว N ครั้ง"** + สองแถวล่าสุด **ทุกรอบ**
③ ตารางอยู่ใน git ⇒ **ลบแล้วเห็นใน diff** (ต่างจากเดิมที่ไม่มีอะไรให้ลบ)

## 🔴 คำเตือนสำคัญเรื่อง 5 แถว `STALE_FLAG` ข้างบน (จดไว้ 14 ต.ค. 2569 22:1x)

- เวลาของทุกแถว **ตกอยู่ในช่วงที่ด่าน `pre-push` รัน `npm test`** ไม่ใช่ตอนใครกด `git commit`
  · commit `4609a834` เวลา 21:32:13 → แถว 21:36:27 (4 นาทีหลัง ระหว่างด่านของ push นั้น)
  · commit `ea2f88ce` เวลา 21:45:26 → แถว 21:51:31 · commit `e87b5dfa` 22:03:29 → แถว 22:08:20
- ช่อง HEAD ของแถวคือคอมมิตที่ **สร้างเสร็จแล้ว** ⇒ เป็นไปไม่ได้ที่จะเป็น commit ที่กำลังถูกสร้าง
- เทสนั้นจงใจเขียน "ธงค้างเก่ากว่า 2 ชม." เพื่อเดินกิ่ง `STALE_FLAG` — ตรงกับช่องที่ขึ้นทุกแถว
