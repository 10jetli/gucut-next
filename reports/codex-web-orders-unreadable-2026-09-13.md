# จอออเดอร์เว็บ: ใบที่อ่านไม่ได้ต้องไม่หายจากความเข้าใจของคนใช้

งาน t_mtx48bgc · 13 ก.ย. 2569 · ฐาน gucut-next 6204713 · branch codex/web-orders-unreadable

ตรวจแล้ว `app/web/orders/page.tsx` มีการแสดง unreadable>0 ตั้งแต่ commit b23d27f อยู่แล้ว ไม่ใช่งานที่ไม่มีใครทำ แต่ยังมีช่องว่างที่แก้ในกิ่งนี้:

- unreadable หาย/null/ผิดชนิด/ติดลบ/ทศนิยม: เดิมตกไปข้อความ “ทั้งหมด N ใบในระบบ” ทั้งที่ไม่รู้ว่าครบ; ตอนนี้แสดง “ยังยืนยันไม่ได้ว่าครบ” พร้อมคำเตือนเหนือตาราง
- unreadable>0 แต่ orders=[]: เดิมมีคำเตือนและยังเขียน “ไม่มีออเดอร์ในหมวดนี้”; ตอนนี้บอกว่าไม่พบในใบที่อ่านได้ และยังยืนยันไม่ได้ว่าไม่มีใบอื่น
- แท็บรวมใช้คำว่า “อ่านได้” เมื่อยังไม่ยืนยันว่าครบ; โหลดล้มไม่โชว์ตัวนับแท็บเก่าราวกับเป็นผลล่าสุด
- orders:null/{} หรือ JSON มี error: เดิมแปลง orders ที่ผิดรูปเป็น [] ได้; ตอนนี้เป็นโหลดไม่สำเร็จ ไม่ใช่ศูนย์
- unreadable=0 ที่เป็นจำนวนเต็มถูกต้องยังแสดงครบ/ไม่มีรายการได้ตามเดิม

ไม่มีการแก้ฝั่ง gucut-web หรือ public/catalog ไม่มีการใช้คีย์จริงหรือเรียก API ร้านเพื่อทดสอบ

## หลักฐาน

`node scripts/tests/web-orders-unreadable.test.mjs` ผ่าน fixture การ render จอจริง 15 กรณี ใช้ React hooks/load เดิมทั้งหมด เปลี่ยนเฉพาะ fetch เป็นคำตอบจำลอง ครอบค่าบวก/ศูนย์/ค่าหาย/ค่าผิดรูป, orders ผิดรูป, HTTP error, และรีเฟรชที่ล้มหลังเคยมี unreadable

สลับซอร์สจอเป็น HEAD เดิมชั่วคราวแล้วรันชุดเดียวกัน: ล้มจริง จากนั้นคืนซอร์สแก้และรันใหม่ผ่าน เพิ่ม react-test-renderer เฉพาะ devDependency ให้คนรีวิวรันซ้ำได้
